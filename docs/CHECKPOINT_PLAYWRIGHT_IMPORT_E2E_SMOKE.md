## Why This Exists

This checkpoint closes the first browser-level automated import QA pilot. The goal was to prove that part of the manual Excel import QA flow can be covered by a small Playwright smoke test without turning it into the full regression matrix.

## What Was Added

- Playwright browser-level QA infrastructure for one import smoke pilot.
- Npm script: `qa:import:e2e`.
- Chromium-only Playwright config.
- One E2E test: `e2e/import-smoke.spec.ts`.
- Runtime workbook fixture helper: `e2e/helpers/importFixtures.ts`.
- `test-results/` ignore rule for Playwright generated output.

## How To Run

```powershell
npm.cmd run qa:import:e2e
```

On a new machine, Chromium may need a one-time install:

```powershell
npx.cmd playwright install chromium
```

## Smoke Test Coverage

The smoke test covers one narrow real-browser flow:

- Open the app in Chromium through the Vite dev server.
- Generate a temporary `.xlsx` at runtime with the existing `xlsx` dependency.
- Upload Excel through the real Import UI.
- Verify one readable row.
- Use AD + SOYAD composition.
- Import Mahalle -> `neighborhood`.
- Import Ilce / Ilce -> `district`.
- Import Telefon.
- Manually map `Veli Adi` to `Veli Ad Soyad`.
- Complete import.
- Open Aday Listesi.
- Select the imported student.
- Verify right drawer values for student name, guardian, location, phone, and note.
- Fail on unexpected page/runtime errors.

## What It Does Not Cover

This is not the full import regression matrix. Out of scope:

- Telefon 1-10 full slot fidelity E2E.
- Telefon 10-only E2E.
- Empty Mahalle/Ilce E2E.
- Only Mahalle / only Ilce E2E.
- Anne/Baba must-not-create-student-name security E2E.
- Export E2E.
- Backup/restore E2E.
- CI integration.
- Broad `data-testid` coverage.
- Production UI or import logic changes.

## Fixture Strategy

Binary `.xlsx` fixture files are not committed in this pilot. The E2E helper generates the workbook at runtime under Playwright output paths. This keeps the first pilot reviewable and avoids binary fixture drift.

## Local Machine Notes

- `test-results/` is generated by Playwright and is ignored.
- `dev-server.log` remains a local untracked runtime helper/log file and must not be staged or committed.
- New machines may require `npx.cmd playwright install chromium`.

## Risks

- This is a smoke pilot, so it proves the browser automation path but does not replace the full manual import regression matrix yet.
- UI text selectors may need narrow `data-testid` support later if copy changes make tests brittle.
- Service worker / IndexedDB cleanup can need care if the E2E suite expands.
- Additional scenarios should be added in small phases to avoid slow and brittle E2E coverage.
